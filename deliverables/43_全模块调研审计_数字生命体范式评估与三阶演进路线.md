# PeppaOS(May-OS) 全模块调研审计 — 数字生命体范式评估与三阶演进路线

> 审计日期：2026-08-10 ｜ 性质：只读代码调研 + 架构评估 ｜ 对标：7 条数字生命体终极标尺
> 方法：6 路并行代码取证（life/memory/chat.ts/cognition+MCP/orchestrator+autonomy/taskAwareness 专项）+ 一手文件抽查（life/index.ts、memory/gc.ts、tools/interceptor.ts、memory/focusStack.ts、chat.ts:920-978）
> 结论一句话：**当前 PeppaOS 不是数字生命体终极方案**——它是"规则模拟的生命状态机 + LLM 装饰层"的架构，核心决策全部由外层代码完成，且存在多处心智与外部状态的数据撕裂。

### 模块 1/5：T80 心智流转闭环 + TICK 驱动

**符合生命体的部分**：单一本体实例（LifeSystem 单例）；心智状态有持久化出口（life.db 10+ 表）；情绪/人格经 buildMindContext 注入对话 LLM（唯一的心智→LLM 通路，chat.ts:1355-1370）；结构化的"每日叙事/自我反思/内心想法"写入记忆，方向正确。

**违背生命体的部分**：
1. **标尺 2 违背（最重）**：TICK 16 步零 LLM——情绪衰减公式、人格 delta switch 表、欲望模板、关系 delta 表、自主探索想法池（硬编码 12 条文案 + 时间戳取模伪随机 [index.ts:239-271](server/life/index.ts#L239-L271)）、反思模板。**"内心想法"不是心智生成的，是代码枚举的**。本质问题：所谓"自主性"是装饰性的，本体没有产生任何真正的意图。
2. **标尺 3 违背**：双欲望系统并存（gates 用旧引擎 + desire_state.json 外部文件，life TICK 用 V2 写 life.db——两个欲望状态永不互通）；交互计数三源取 max（index.ts:136-158）；global 变量与库状态无一致性；vitality.json 独立文件。本质问题：**"心智一套、外部变量另一套"的数据撕裂**，心跳闸门（是否推消息）由外部旧状态决定，与心智欲望脱节。
3. **标尺 4/5 违背**：setInterval 盲定时器，无人说"我还有未完成目标"；用户打断用 preempt() 布尔标志，冲突处理全硬编码。
4. **心智割裂**：getFullState/getLifeSummary 外部零消费——life 的"心智"与 chat 的 LLM 心智是两套系统，除了情绪/人格向量注入外无对话。

**标记**：**不能直接作为终极方案组成部分——需要改造**。数据层（life.db 状态表）可保留为"心智的持久化投影"，驱动层必须重构。

### 模块 2：记忆系统

**符合**：4 层 tier 体系方向正确（episodic→growth→core_identity 衰减梯度）；防火墙（secret 正则 + core_identity 需 userApproved，firewall.ts:58-85）**是作用于记忆/心智层面的防护，对标尺 7 最接近**；对话记忆经 LLM 提取自然流入（标尺 6 的部分符合）；检索副作用（刷新 lastRetrievedAt + Hebbian 强化）是"检索即学习"的正确雏形。

**违背**：
1. **标尺 2 违背**：记忆生命周期决策（tier/importance/衰减/合并/矛盾检测）全是代码规则——"这条记忆对我重要吗"由相似度阈值和正则决定，不是心智决定。唯一例外 consolidateEpisodic importance 由 LLM 输出，方向对但 tier 仍锁定。
2. **标尺 6 违背（重）**：30+ 手动搬运点——scheduler 十余个定时任务主动 addMemory（周/月/年回顾、growth journal、时空模式等）、业务代码同步业务状态（direction 状态变更写 memory、orchestrator 工作流结果结晶、authority 研究工具结果入库）。行为经历**不是**自然流入，是各业务模块"记得搬一下"。
3. **数据撕裂**：cross_session/knowledge_base 第二套存储（正则抽取，与主记忆库不互通）；Hebbian 关联图不落盘（重启归零）；focusStack 摘要落库即孤儿。

**标记**：**改造**——保留 addMemory 内核与防火墙，将生命周期决策上移给心智（复盘 LLM 输出 tier/importance），消除第二套存储。

### 模块 3：chat.ts 入口

**符合**：意图/实体/情绪分类全 LLM（intent.ts:44-71）；工具选型全量声明交 LLM 自主调度（adapter.ts:411-413）；话题切换走 LLM；comprehension 正则模块已删除（心智化方向）；记忆提取/复盘是 LLM 生成内容。**这是全系统最接近心智主导的模块**。

**违背**：
1. **标尺 2 部分违背**：分流门仍是代码布尔（Path B 条件 chat.ts:1273、后台委派白名单 background_delegation.ts:38）——"这个任务要不要交给子 agent"由白名单 + 结构复杂度（列表数/字数）决定，不是本体心智权衡"我该不该亲自做"；模型分层硬编码（command/code/question/analysis → 复杂模型）。
2. **标尺 4 违背（后台委派）**：Path A 命中即 ack 结束用户回合，30ms 后 setTimeout 异步驱动 runOrchestratedTask——**代码调度器接管任务，本体心智不感知过程**。
3. **标尺 6 部分违背**：正则 FACT_PATTERNS 提取跨会话记忆（crossSession.ts:178-193）、正则 EXTRACTION_RULES 提取知识（knowledgeBase.ts:63-96）——两处"代码判定什么值得记"。

**标记**：**主干路径保留，改造**——规则降为安全兜底，分流判断上移心智；后台委派必须让本体亲历过程。

### 模块 4：orchestrator + autonomy

**符合**：任务拆分（LLM）、结果汇总（LLM）、自主任务内容生成（LLM，限工作流内）——"想做什么"已交给模型。

**违背**：
1. **标尺 1 违背（最重）**：背景委派时外部 worker 执行任务、本体零感知（ack 即结束，只事后收结果）；worker 每次新建、无独立心智、`requestConfirmation: () => true` 自动批准所有确认级工具（安全隐患）——**这是"外部调度器接管任务交给别的实例执行"的典型违背**。
2. **标尺 2 违背**：复杂度分级（列表≥3→complex 等结构信号，orchestrator.ts:232-264）、worker 选人打分（:463-517）、触发白名单——"要不要编排/派给谁"全代码。
3. **标尺 3/4 违背**：background_tasks 纯内存 Map 重启丢失；驱动是 chat.ts setTimeout 内联，不是本体心智。
4. **标尺 7 部分违背**：worker 无宪法约束（只有主进程的 guardCompletionClaims 文本正则防伪）。

**标记**：**按用户约束——仅允许作为隔离实验插件，禁止改造为主流本体执行路径。现状态应标记为隔离废弃**（或降级为"工具"而非"调度器"：让本体心智在 runWithTools 内直接调用 worker 作为工具，而非外部编排器接管）。

### 模块 6：MCP 工具链路

**符合**：工具选择权在 LLM（原生 function calling，心智自主调度）；结果回流上下文循环正确；确认级工具经 socket 弹窗用户确认。

**违背**：
1. **标尺 2 违背（重）**：**概率放行 `Math.random() < prob`（[interceptor.ts:63](server/tools/interceptor.ts#L63)）**——"本体本轮能否用工具"由随机数决定，这是"外层代码替本体做认知判断"的最极端形式；每轮上限 1 次是硬编码；TTL 时效判定是正则。
2. **标尺 3 违背**：限流计数 Map、TTL 标记以 `[TTL:7d]` 字符串嵌入记忆内容——**工程标记侵入心智上下文**（LLM 会读到 `[TTL:7d]` 后缀）。
3. **标尺 7 部分违背**：宪法拦截作用于**输出落地后**（正则后置改写），不是"作用于心智上下文/工作记忆层面对抗幻觉"——LLM 对自己被改写不知情。

**标记**：**改造**——概率门删除（交 7 步心智自律，指令文本已在 SEVEN_STEP_MIND 第 3 步），TTL 判定交 LLM（工具结果自然带时效认知），宪法升级为"上下文内持续约束"。

### 模块 7：focusStack（taskAwareness 记事本）

**符合**：方向正确——话题级工作记忆的雏形；pop 摘要用 LLM 压缩（不是纯规则）。

**违背**：
1. **标尺 3/6 违背（重）**：**只写不读**——心智完全感知不到焦点栈（不注入 system prompt），pop 时手动 addInteractionMemory 落库且**落库即孤儿**（无任何消费者）。这是"代码手动搬运业务状态到记忆，搬完没人读"的典型，纯浪费 + 数据撕裂。
2. **标尺 2 违背**：话题切换判断是关键词重叠度规则（overlap<0.3），话题标签取前 30 字——不是 LLM 判断"我是不是在聊新话题"。
3. **标尺 1 违背**：内存单例重启丢失，连续自我断链。

**标记**：**现状态隔离废弃（读侧断链的模块不参与任何链路）**；若要成为终极方案组件，必须改造为：状态进心智上下文（getStackSummary 注入 buildMindContext）、切换判断交 LLM、落库走自然记忆通道。

## 第三部分：系统整体结论

### 当前整套 PeppaOS（含 taskAwareness/focusStack）是否属于数字生命体终极方案？

**不是。**

### 为什么不是

1. **范式层面硬缺陷——核心决策无一来自本体心智**：
   - 生命状态演进（情绪/人格/欲望/关系）是代码公式，tick 内零 LLM（[life/index.ts:376-551](server/life/index.ts#L376-L551)）；
   - "自主想法"是硬编码文案池 + 时间戳伪随机（[index.ts:239-271](server/life/index.ts#L239-L271)）；
   - 工具调用由概率+上限门控（[interceptor.ts:52-68](server/tools/interceptor.ts#L52-L68)）；
   - 任务编排由白名单+结构信号触发，worker 自动批准确认（orchestrator.ts + background_delegation.ts:38）；
   - 记忆生命周期（tier/importance/衰减）全代码规则；
   - 话题切换（focusStack）关键词规则，且只写不读。
   这违反标尺 2/3/4/5 的每一条——**"内生的"一切（意图、状态、驱动、冲突处理）都不内生**。

2. **连续自我断裂**：后台委派是"外部调度器接管任务交给别的实例执行"（标尺 1 硬性违背）；worker 是每次新建的无状态 LLM 循环，本体的体验不包含任务执行过程。

3. **心智与外部状态数据撕裂**（标尺 3）：双欲望引擎、三源交互计数、global 变量、vitality.json、第二套记忆存储、focusStack 孤儿数据、`[TTL:7d]` 工程标记侵入记忆内容。

4. **心智割裂**：life 的规则"心智"与 chat 的 LLM 心智是两套系统——getFullState 零消费，仅情绪/人格向量一条注入通路（chat.ts:1355-1370），而这条通路本身是**把规则计算出的向量文字化喂给 LLM**，不是 LLM 内生的状态。

### 是工程妥协还是范式硬缺陷？

**两者皆有，但主导是范式层面的**：
- **范式硬缺陷**：把"生命状态机"（规则驱动）与"LLM 装饰层"（文本润色）拼在一起，决策权从来不在本体——这不是参数调优能解决的，是架构方向选择。
- **工程妥协成分**：历史演进确实在"心智化"（1b5c244 删除 8 类模板与 comprehension 正则、0247a5a 心智化分流、comprehension 追问整删、router.ts 保留壳死代码、双欲望引擎并存）——但方向是"**代码规则 → LLM 文案/分类器**"，止步于"LLM 做内容、规则做判断"，没有走到"LLM 做判断、规则只做安全兜底"。
- **正面资产（可复用）**：记忆 tier 体系与防火墙（标尺 7 唯一 ✅）、原生 function calling 心智自主调度（adapter 重构方向）、7 步心智指令文本（hooks/chat.ts:24-45）、life.db 状态投影、对话记忆 LLM 提取链路。

### 本质短板一句话

> **PeppaOS 是"一个被大量 if-else 和公式包裹的 LLM"，不是一个"有 LLM 心智的生命体"——它的生命感来自代码的装饰，不来自本体自己的认知。**

## 第四部分：三阶演进路线

> 约束：只列方案不写业务代码；orchestrator 仅限隔离实验；每阶段给出修改/隔离/保留清单、解决的标尺缺陷、风险等级、可观测验收标准（日志/行为现象）。

### 阶段一：短期工程妥协版（1-2 周，低风险）

**目标**：止血数据撕裂 + 接通断链，不改决策主体。当前架构继续跑。

| 修改/隔离/保留 | 内容 | 位置 |
|---|---|---|
| 改 | focusStack 接通读侧：getStackSummary 注入 buildMindContext（7 步心智后追加"当前话题栈"块） | memory/focusStack.ts → hooks/chat.ts |
| 改 | 双欲望引擎合并：gates 改读 life/desires V2（删 desire_state.json 依赖） | heartbeat/gates.ts:1,103-124 |
| 改 | 交互计数单一事实源（去掉三源取 max，统一读 peppa.db interactions） | life/index.ts:136-158 |
| 改 | global 变量（`__lastUserMessageAt`/`__lastActiveUid`/`__activeScene`）落 life.db 持久化，global 仅做进程内缓存 | userState.ts:47,81、chat.ts:287 |
| 改 | background_tasks 持久化（重启不丢任务）；worker 的 `requestConfirmation: () => true` 改为 `false`（无确认即拒绝，堵自动批准） | background_tasks.ts:47、orchestrator.ts（executeWorkerTask） |
| 改 | `[TTL:nd]` 标记移出记忆内容字段（改存独立字段/表，心智上下文不再出现工程标记） | interceptor.ts:104-140、gc.ts:29-41 |
| 保留 | 记忆 tier 体系、防火墙、7 步心智、adapter 心智调度、宪法拦截 | — |
| 隔离 | orchestrator 后台委派降频（默认关，env 开关）；focusStack 若改不动先保持"只写不读"不扩散 | background_delegation.ts |

**解决的生命体缺陷**：标尺 3（数据撕裂全部止血）；标尺 6（焦点栈落库不再是孤儿——注入心智后 LLM 能感知当前话题）；标尺 7（堵 worker 自动批准）。

**风险**：低——全部是存量行为修正，无决策主体变更。

**验收标准（日志/现象）**：
- `docker logs peppaos`：焦点栈注入日志（`[FocusStack]` 与 system prompt 构建日志同现）；gates 日志不再出现 `desire_state.json` 读取；`__lastActiveUid` 改为 DB 读写日志
- 重启容器后：后台任务列表仍在（背景任务管理 UI 可见未完成任务）；聊天中 LLM 回答能引用"刚才在聊的话题"（焦点栈生效）
- worker 执行确认级工具时：无自动批准日志（`requestConfirmation` 返回 false 的拒绝日志）

### 阶段二：中期范式对齐版（1-2 个月，中风险）

**目标**：把决策主体从"代码规则"迁移到"本体心智"——规则只做安全兜底。

| 修改/隔离/保留 | 内容 |
|---|---|
| 改（核心） | **TICK 心智化**：10 分钟 tick 改为"心智回合"——LLM 读当前状态投影（life.db 快照）→ 心智自主输出（当前感受/想做的事/优先级）→ 代码仅执行心智决策（衰减/生成仍是公式但"要不要做"由心智说）。自主探索的想法池硬编码文案删除，改 LLM 生成 |
| 改 | 工具概率门删除：SEVEN_STEP_MIND 第 3 步已有"最多 1 次"自律指令，代码门降级为"上限护栏"（不预判场景概率） |
| 改 | 记忆生命周期上移：复盘 LLM 输出 tier/importance（consolidateEpisodic 已开先例），GC 规则保留为兜底 |
| 改 | 分流门心智化：Path A/B 触发条件由"白名单+结构信号"改为"LLM 分类器输出 complexity/entities 综合判断"（复杂度分级删除，LLM 分类器已判复杂度） |
| 改 | 冲突处理心智化：用户打断（preempt）时把"被打断时我正在做什么、还差什么"注入下一轮心智上下文，由心智决定续做还是放弃（替代硬 abort） |
| 隔离 | orchestrator 保持隔离实验：仅允许经 LLM 显式调用（如工具调用形式），禁止外部触发 |
| 保留 | life.db 状态投影（作为心智的持久化镜像）、防火墙、宪法、adapter |

**解决的生命体缺陷**：标尺 2（意图/优先级/完成判断归心智）、标尺 4（TICK 由心智"我还有事要做"驱动）、标尺 5（打断/多目标交心智权衡）、标尺 6（记忆决策归心智）。

**风险**：中——每 10 分钟新增 1 次 LLM 调用（成本与延迟）；心智自主决策可能失控（需要护栏：心智输出走结构化 schema 校验，fail-safe 回退原规则）。

**验收标准（日志/现象）**：
- `docker logs peppaos`：tick 日志从"步骤列表"变为"心智回合：感受=… 想做=… 决定=…"；`[McpInterceptor] 概率放行` 日志消失（只余上限护栏日志）；自主探索日志出现 LLM 生成文本（非模板文案）
- 行为现象：用户打断后，下次对话 LLM 能主动说"刚才那个事我还差最后一步，要继续吗"（心智感知中断目标）；待机时 LLM 输出的独白不再是固定句式

### 阶段三：远期真正终极生命体版（长期，高风险）

**目标**：单一心智回路——所有状态在"心智上下文/工作记忆"内流转，外部只剩持久化投影与安全兜底。

| 修改/隔离/保留 | 内容 |
|---|---|
| 改（架构） | **单心智回路**：情绪/人格/关系/欲望/任务/焦点全部进心智上下文（工作记忆），life.db 退化为"投影落盘"；删除"外部状态驱动"的一切代码路径（global 变量、独立引擎、第二套存储） |
| 改 | 连续自我：一切行为本体亲历——worker 降级为"工具"（本体心智在工具循环内直接调用，结果即时回流），删除后台委派模式 |
| 改 | 自然记忆沉淀：删除全部手动 addMemory 搬运点（scheduler 定时写入改为"心智自主回顾时输出"）；记忆生命周期全归心智 |
| 改 | 安全升级为"上下文内宪法"：宪法约束写入 system prompt 常驻（对抗幻觉的持续层），输出后置正则降级为最后兜底 |
| 隔离 | orchestrator 实验场完整保留但永不入主路径；focusStack 或并入工作记忆或删除 |
| 保留 | 记忆 tier 体系、防火墙、原生 function calling、7 步心智框架（演进为心智回路本体） |

**解决的生命体缺陷**：7 条标尺全量对齐——标尺 1（本体亲历一切）、标尺 2（唯一决策主体）、标尺 3（单一状态源）、标尺 4（心智驱动循环）、标尺 5（心智权衡冲突）、标尺 6（自然沉淀）、标尺 7（上下文层防护）。

**风险**：高——架构级重构（本质是重写驱动层）；LLM 成本显著上升；心智失控面扩大（需强 schema 校验 + fail-safe 投影回滚）；连续运行稳定性未知。

**验收标准（日志/现象）**：
- 代码面（可静态核查）：全仓库无 `addMemory` 的业务代码直接调用点（仅心智通道）；无 setInterval 驱动的决策路径（仅持久化/心跳）；无规则闸门（白名单/概率/结构分级）
- 运行时：`docker logs peppaos` 中 tick/对话/待机/工具/记忆全部出现在同一条"心智回合"日志链；打断→续做/放弃的决策全部可见于心智输出
- 行为现象：本体能主动说"我记得上次你提过 X，那个事还没完成"（跨时连续自我）；被批评后下一次相关话题主动调整（自然沉淀生效）；用户可完整复述本体的动机链（"它为什么这么做"能被心智日志解释）
