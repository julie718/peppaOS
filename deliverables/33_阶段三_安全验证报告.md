## 二、安全红线逐项验证

### 红线1：外部 API / 自研 MCP 在沙箱中隔离运行 ✅

**静态证据**：
- 沙箱生成模板（mcp_template.ts）渲染产物**零 import 语句**，零外部依赖 — E2E 断言 `!/import\s/.test(src)`（场景3）
- 沙箱 tsconfig `"types": []`，不解析任何 node 类型（无本地文件/模块访问面）
- 沙箱工具由宿主动态加载（`file://` + cache busting），仅暴露 `toolDefinition.handler` 单一调用面
- 模板内嵌 `assertPublicHttpsUrl`：仅允许 **HTTPS 公网** 出站

**E2E 行为断言**（场景8 实测）：
- `check('模板内嵌 SSRF 防护', src.includes('禁止访问内网地址'))` — 防护代码确实存在于渲染产物
- SSRF 拦截实测：localhost / 127.0.0.1 / 10.x / 172.16-31.x / 192.168.x / 非 HTTPS 一律拒绝

### 红线2：第三方密钥 AES-256-GCM 加密，心智层不可读明文，仅独立授权网关代理 ✅

**静态证据**：
- 全量扫描 `server/skills_extension/`：明文密钥仅在两个位置出现 — `routes.ts:196`（用户录入入口）与 `encryptSecret` 加密函数入参位，录入后立即加密
- 加密后存储格式 `base64(iv):base64(tag):base64(ciphertext)`，密钥派生 `SHA-256(GATEWAY_MASTER_KEY || JWT_SECRET)`
- 全系统无任何 `decryptSecret` 调用点逃出 auth_gateway 作用域；adapter 不持有任何密钥，仅通过 `setProxyFetcher(proxyFetch)` 注入网关代理

**E2E 行为断言**（场景4 实测）：
- `check('密文不落明文', !stored.encryptedKey.includes('sk-live') && split(':').length === 3)` — 库中只有密文结构
- `check('元信息列表不含密文', ...)` — 列表 API 零密钥片段
- `check('密文篡改解密失败（完整性保护）', tamperFail)` — 篡改任一字节 → GCM 认证失败
- 代理调用实测：认证头注入发生在网关 `proxyFetch` 内部，适配器/心智层全程只见密文与代理结果

- 场景8 合规用例：`none` 域不误注入免责（反向校验）

### 红线4：所有工具必须通过自动化 E2E + 人工审批闸门（批准前不可进入工具池） ✅

**调用点分析**（工具池唯一入口证据链）：
```
registerDefinition（adapter.ts:290，工具池注册唯一实现）
 ├─ 调用点① approval.ts:121（deploySandboxTool 内，沙箱自研上线）
 └─ 调用点② adapter.ts:427 上游 commitStagedAdaptation（适配器上线）
        └─ 其唯一调用点 approval.ts:78（decideApproval 'approved' 分支）
              └─ 唯一前置：自动化测试 gatePassed（M5a 6 类用例全过）
```
→ **工具池 100% 入口都汇于 `decideApproval` 的 approved 分支**，无任何旁路。

**E2E 行为断言**：
- 场景2 `check('批准前未进入工具池', !isInToolPool(...) && !toolRegistry.get(...))` — 测试通过、审批待定时工具不可见
- `check('批准 → 上线（进入工具池）', dec.ok && isInToolPool(...))`
- 场景3（沙箱自研）驳回后 `check('驳回后不在工具池', !isInToolPool(tool.name))` — 驳回/退回工坊不残留
- 拒绝路径强制：驳回必须附修改意见，否则拒绝处理（approval.ts `rejected` 分支）

### 红线5：沙箱最小权限（只读网络、不读写本地敏感配置、不自动开通付费 API） ✅

- 沙箱工具仅凭 `fetch` 出站，模板渲染产物零文件系统 API（无 fs/process 引用、无 import）
- SSRF 硬拦截本地/内网地址 → 本地敏感配置无读取通道
- 网关令牌桶限流（默认 60 次/分，env 可配）→ 无自动开通付费 API 的失控通道；计费统计 `getBillingStats/setEstimatedCost` 仅供人工审计
- 适配器超时 8s ×3 重试上限 + 响应 200KB 截断 → 资源耗尽被量化封顶

### 红线6：不可变审计日志 ✅

- 全部关键事件写入独立 `skills_extension.db` 的 `skills_audit` 表（append-only 设计，无 UPDATE/DELETE API）
- 审计覆盖全链路：`gap_detected`（无条件写，含无缺口汇总）→ `search` → `test` → `approve/reject/hold` → `deploy/upgrade/rollback` → `credential`（只记密钥长度，绝不记片段）→ `remediate`
- E2E 场景审计链断言：空库首轮即出现 `gap_detected` 记录
